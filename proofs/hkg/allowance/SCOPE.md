# HKG allowance verification scope

## Program boundary

The claims execute the supplied 2,091-byte runtime image from program counter
zero with an empty EVM stack and memory. They select
`allowance(address,address)` through canonical ABI calldata and execute the
dispatcher, Solidity ABI decoder, nested mapping address calculation, storage
load, and ABI return or nonpayable rejection to `#halt`. No source-level
replacement rule summarizes the runtime execution.

## Input domain

`OWNER` and `SPENDER` are arbitrary 160-bit addresses. `STORAGE` is a
symbolic EVM storage map; the result uses the semantics' total `#lookup`, so
an absent nested-mapping slot denotes zero. `ACCT` is an arbitrary 160-bit
executing account. The success claim covers call value zero. The unsuccessful
claim covers every nonzero 256-bit call value with otherwise canonical
allowance calldata.

Calls whose selector or ABI shape does not identify `allowance`, internal
calls into the middle of the runtime, and resource-exhaustion behavior are
outside this function-specific theorem.

## Observable final state

The success claim observes `EVMC_SUCCESS`, a 32-byte ABI return containing
`#lookup(STORAGE, #hashedLocation("Solidity", 2, OWNER SPENDER))`, and
preservation of the executing account's complete storage map. The failure
claim observes `EVMC_REVERT`, empty return data, and the same storage map.
The final internal stack, memory, program counter, and memory high-water mark
are existentially framed because they are not externally observable after
halting. All omitted configuration cells are framed and unobserved.

## Intended property

For a canonical zero-value call, the runtime returns the allowance stored in
`allowed[owner][spender]` and does not mutate storage. For the same call with
nonzero value, the compiler-generated nonpayable guard reverts with empty
output and does not mutate storage.

## Chosen contract readings and execution environment

- The source declaration order gives `totalSupply` slot 0, `balances` slot
  1, and the nested `allowed` mapping slot 2; Solidity mapping layout is
  expressed by `#hashedLocation("Solidity", 2, OWNER SPENDER)`.
- The bytecode, not an idealized ERC-20 interface, is authoritative. In
  particular, an absent storage key returns zero via EVM `SLOAD`.
- `BYZANTIUM` is selected because this runtime contains opcode `REVERT`;
  it is the earliest modeled schedule on which that opcode has its intended
  semantics. Gas accounting is disabled (`<useGas> false`) so the theorem
  describes functional behavior independent of a particular gas budget.
- The call executes in `NORMAL` mode at an arbitrary valid contract account.
  Caller, origin, balances, block fields, logs, and transient state are
  unobserved because this read-only function neither consults nor changes
  them on either covered path.
- “Unsuccessful call” is read as the function-specific nonpayable rejection
  generated by this compiled runtime. Malformed selector/calldata behavior and
  out-of-gas termination are dispatcher/resource properties rather than the
  implemented allowance body and are explicitly excluded.
